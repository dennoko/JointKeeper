既存衣装のウェイト構造を活かしつつ、NDMFベースで非破壊に「肘・膝の補助ボーンとウェイト再計算」を行うUnity拡張機能のコンセプトおよび開発要件定義をまとめました。

---

## 1. プロジェクトコンセプト

* **プロジェクト仮称:** NDMF Elbow & Knee Helper（または Joint Volume Keeper）
* **コアコンセプト:**
「部分露出衣装でも素体を消さずに済む、Unity完結・完全非破壊の関節ボリューム維持ツール」
* **解決する課題:**
半袖・破れ加工・スリット・タイト衣装など「素体メッシュを削除できない衣装」において、肘・膝を深く曲げた際に発生する**メッシュの体積減少（潰れ）による素体貫通**を、Blenderを使わずUnity上の非破壊ワークフローだけで解決する。
* **技術的アプローチ:**
ゼロからウェイトを塗るのではなく、**「既存の親ボーン（UpperArm/UpperLeg）と子ボーン（LowerArm/LowerLeg）のブレンド比率」から補助ボーンのウェイトを数理的に自動算出・再分配**することで、衣装本来の自然な変形を維持したまま関節の尖り・厚みを保つ。

---

## 2. システム要件（機能要件）

開発スコープをフェーズ1（MVP：ビルド時自動生成＋最低限のGUI）**と**フェーズ2（UX強化：Sceneビュー上のインタラクティブ編集・曲げプレビュー）に分けて定義します。

### 【フェーズ1】コア機能・NDMFビルドパイプライン（MVP）

1. **対象部位の自動認識・設定コンポーネント**
* アバターのHumanoid設定（`Animator.GetBoneTransform`）から左右の `UpperArm` / `LowerArm` / `UpperLeg` / `LowerLeg` を自動取得。
* 対象となる衣装の `SkinnedMeshRenderer` を複数指定可能にする（手動指定またはアバター配下からの自動検出）。
* 部位ごとの有効/無効トグル（右肘・左肘・右膝・左膝）。


2. **補助ボーンの非破壊生成とリグ組み込み（NDMF Pass）**
* ビルド時（またはプレイモード突入時）に各関節位置へ補助ボーン（例：`JK_Helper_LeftElbow`）を自動生成（ウェイト影響頂点が 0 の関節では生成をスキップ）。
* コンストレイントは **VRChat SDK 標準の `VRCParentConstraint` に統一**（保守性・ロール差耐性・Quest 対応を重視）。ソースごとの `ParentRotationOffset` により親・子ボーンの中間角度（デフォルト `0.5`）を安全に追従させる。
* 曲げ角度に応じた**押し出し（スライド/オフセット）挙動**は、FX レイヤーや Animator を使わず `VRCParentConstraint` の**対称軸 `ParentPositionOffset`** で実現する（例：90度曲げた際に肘頭・膝蓋骨方向へ数mm外側へ押し出す）。位置・回転は常に全軸有効とし、押し出し量の値によって挙動が不連続にならないようにする。
* 外側（押し出し）方向は、Humanoid マッスル空間で測定した**実際の曲げ軸**から求める（VRChat の IK と同じ軸）。測定できない場合はレスト形状から推定する。


3. **既存ウェイトからの自動ウェイト再計算アルゴリズム**
* `LowerArm` 等の**ツイスト対策補助ボーン**（`LowerArm_Twist` 等）を考慮し、単一ボーンではなく `VRCPhysBone` を除外した**近位ボーン群（$G_P$）・遠位ボーン群（$G_D$）**として `SkinnedMeshRenderer` の既存ウェイトを解析する。群の分類は、ボーン名ではなく「親子関係とコンストレイントのソースが近位・遠位のどちらに依存するか」（運動学的依存）で決める。
* 初期状態で非アクティブなトグル衣装も処理対象に含める。
* 親側グループと子側グループのウェイトが混在している境界領域を自動検出し、**角モーメント保存式**により元の曲げ追従中心を保ったまま補助ボーンへウェイトを再分配する（グループ内のツイスト比率と外部 PhysBone ウェイトは保持）。
* **VRChat の 1 頂点あたり最大 4 ボーンインフルエンス制限**に厳密準拠し、4 スロットが埋まっている頂点では**同一グループ内統合（例：`LowerArm_Twist` → `LowerArm`）を最優先とする 4 段階スロット統合**で破綻を防ぎつつ総和 `1.0` を維持する。
* 影響範囲（軸方向/径方向の楕円体 Radius・Falloff）および補助ボーンへの分配強度（Strength）・カーブ指数をパラメータ化する。



### 【フェーズ2】エディタUX・プレビュー機能（プレイモード不要の調整体験）

1. **Sceneビュー上のギズモ（Gizmo / Handles）表示**
* Editモード（非プレイ時）で、補助ボーンの生成予定位置・外側方向ベクトル・影響範囲の楕円体ワイヤーフレームをSceneビュー上に可視化し、ハンドルで直感的に微調整可能にする。


2. **非破壊・リアルタイム関節曲げ＆ツイストプレビュー（最重要UX）**
* **プレイモード（GestureManager等）に入らずに**、Inspector上のスライダーで**曲げ角（0°〜150°）**および**前腕ツイスト角（-90°〜+90°）**を動かすだけで、Sceneビュー上のアバターと衣装の変形結果・素体貫通・ツイスト破綻をリアルタイムに確認できる機能。
* 元アバターは一切変更しない。**NDMF Preview System（`IRenderFilter`）**の代理レンダラーと、非保存の「影ボーン」階層だけで曲げ・ツイストを表示することで、プレビュー中の保存（`Ctrl+S`）やリロードでもシーンを汚さない安全設計とする。MA のプレビュー（Scale Adjuster 等）とも同じ仕組みの上で共存させる。


3. **ウェイト分布・4ボーン診断ヒートマップ表示**
* Sceneビュー上で、再計算後の補助ボーンウェイトの乗り具合をカラーグラデーション（青→緑→赤）でプレビュー表示する。
* あわせて 4 ボーン制限によるスロット統合・保護スキップが発生した頂点を色分け確認できる診断表示モードを備える。

## 3. 非機能要件・技術的制約

* **NDMFパイプラインの実行順序（Execution Phase）:**
* Modular Avatar（`MA Merge Armature` / `MA Scale Adjuster` 等）によるボーン統合・スケール調整が**完了した後**に補助ボーンを追加・ウェイト計算を実行する必要があるため、`BuildPhase.Transforming` にて **`AfterPlugin("nadena.dev.modular-avatar")`** かつ **`BeforePlugin("com.anatawa12.avatar-optimizer")`** に配置する。
* 複製・書き換えたメッシュは（MA と同じ規約で）`ObjectRegistry.RegisterReplacedObject` に登録し、NDMF のオブジェクト追跡・エラーレポートと整合させる。補助ボーンは `VRCParentConstraint` を持つため、後続の AAO（Avatar Optimizer）のメッシュ結合・ボーン統合でも削除されない。
* VRCFury（Armature Link）の衣装は NDMF Transforming より後で統合されるため、現時点では非対応（警告を出してスキップ）。


* **VRChat パフォーマンスランク・制約への配慮:**
* コンストレイントは保守性とクロスプラットフォーム互換性（PC / Quest）を重視し、Unity 標準 Constraint ではなく **VRChat SDK ネイティブの `VRCParentConstraint` に統一**する（各補助ボーンあたり Constraint Count = 1。Constraint Depth は通常 1、ソースが既に Constraint 駆動のツイストボーン等の場合はその深さ + 1）。
* **複数コンポーネント配置時のボーン共有ポリシー:** 同一関節でリグ設定（追従率・押し出し量・ピボット・ソース等）が一致する場合は、ビルド内レジストリにより**同一の補助ボーンを複数衣装で共有**しボーン増加を抑える（標準構成で最大 4 本）。一方、衣装ごとに異なるリグ設定が指定された場合は、コンストレイントボーンの負荷が比較的軽微であることを踏まえ、**設定が異なる場合のみ追加ボーンの生成を許可**する。
* **最大 4 ボーンインフルエンス制限の厳守:** 出力メッシュは常に VRChat ランタイム規格に準拠した 1 頂点あたり最大 4 ボーン・降順ソート・総和 `1.0` に正規化する。


* **非破壊性の担保:**
* 元のFBXや `.mesh` アセットは一切書き換えず、影響頂点が 1 つ以上存在する `SkinnedMeshRenderer` にのみビルド時に `Mesh` を複製（`Instantiate`）して `boneWeights` と `bindposes` を更新する。
* Authoring コンポーネントは `VRC.SDKBase.IEditorOnly` を実装し、NDMF ビルドの `finally` ブロックで確実に除去する。


* **対象Unity / SDK環境:**
* Unity 2022.3.22f1（VRChat現行推奨環境）
* NDMF（Non-Destructive Modular Framework） 1.x 系（Phase 2 プレビューは `IRenderFilter` を含むバージョンが必要。開発環境：NDMF 1.14.6 / Modular Avatar 1.18.3 / VRChat SDK 3.10.5）
* VRChat SDK - Avatars 3.7.0 以降（`VRCParentConstraint` 等 VRC Native Constraint 対応バージョン）

## 5. 設計上の重要ポイント（開発時の勘所）

* **「外側（肘頭・膝蓋骨側）」と「内側（折り目側）」の非対称処理（位置ベース判定）:**
  肘や膝の関節は、内側（曲がる方向）の頂点を補助ボーンに強く追従させると逆にメッシュが突き出して破綻します。関節の曲げ方向ベクトルを基準に、「外側（伸びる側）にのみ強くウェイトを割り当て、内側（縮む側）は既存のウェイトを維持する」フィルタリングを入れます。このとき**頂点法線ではなく骨芯からの径方向位置**で判定することで、厚みのある衣装（表面＋裏面ライニング）の表裏が同じウェイトになり自己貫通を防げます。
* **ツイスト補助ボーン（`LowerArm_Twist` 等）と 4 ボーン制限の共存:**
  前腕ツイスト補助ボーンを持つアバターでは `LowerArm` 自体にウェイトが無く `LowerArm_Twist` に乗っている場合や、4 スロットが既に満杯の頂点が頻出します。近位/遠位ボーン群としての集約と、4 スロット衝突時の「同一グループ内統合（例：`LowerArm_Twist` → `LowerArm`）」により、曲げ角モーメントと PhysBone ウェイトを壊さずに補助ボーンを挿入します。
* **既存ボーン基準の Bindpose 算出（近位/遠位ブレンド）:**
  `smr.transform` ではなく、既存スキニングボーンの `localToWorldMatrix * bindpose`（スキニング行列）から補助ボーンの `bindpose` を逆算します。ただし、上腕側と前腕側のスキニング行列は、衣装ボーンが bind pose から動かされている（非対応衣装のフィッティング、MA の bindpose 書き換え後など）と一致しません。そのため、単一ボーン基準ではレスト姿勢で数 mm ずれます。**近位・遠位の行列を追従率 α でブレンド**した行列から逆算することで、FBX インポートスケール・`MA Scale Adjuster`・ボーン調整済み衣装でもレスト姿勢のズレをゼロに保ちます。残りのズレはビルド時に実測し、閾値を超えたら警告します。

## 6. 確定済み設計決定（Architecture Decisions）

詳細設計は [ARCHITECTURE.md](./ARCHITECTURE.md) に定義しています。主な確定事項は以下の通りです。

| 項目 | 決定内容 | 理由 |
| :--- | :--- | :--- |
| **コンストレイント構成** | **`VRCParentConstraint` に統一**（位置・回転とも常時全軸有効） | 単一コードパスによる高い保守性、ソース別 `ParentRotationOffset` によるロール差吸収、対称軸オフセットによる Animator 不要の曲げ連動押し出し、低 Depth・Quest 対応の両立。 |
| **複数コンポーネント時のボーン共有** | **リグ設定が同一なら共有、設定が異なる場合のみ追加ボーン生成を許可** | コンストレイントボーン増加のパフォーマンス負荷が比較的軽微であるため、衣装ごとの個別押し出し量調整などの自由度を確保しつつ重複生成は防止。 |
| **ウェイト再分配方式** | **近位/遠位ボーン群集約 ＋ 角モーメント保存式 ＋ 4 段階スロット統合** | ツイスト補助ボーン構成と VRChat 最大 4 インフルエンス制限・PhysBone 共存を数学的に破綻なく処理するため。 |
| **ボーン群分類** | **運動学的依存分類**（名前・位置ヒューリスティクスを使わない） | 剛体子ボーンは名前に関係なく親と同じ曲げ運動をするため。取りこぼしと誤包含を同時に防ぐ。 |
| **外側方向の決定** | **Humanoid マッスル空間からヒンジ軸を実測** | VRChat の IK と同じ軸で曲がるため、押し出し方向とウェイト範囲が一致する。 |
| **補助ボーン Bindpose** | **近位/遠位スキニング行列のブレンドから逆算** | 衣装ボーンが bind pose から動かされていてもレスト姿勢のズレをゼロに保つため。 |
| **Phase 2 プレビュー基盤** | **NDMF Preview System（`IRenderFilter`）＋影ボーン** | 開始が軽く、MA のプレビューと共存でき、後始末をフレームワークに任せられるため。 |
